# Equivalence contract (R ↔ Python)

Reference: R implementation **CCLasso v2.0** (`tests/r_reference/reference/R/cclasso.R`).
Fixtures: `tests/golden/` (committed, generated by `tests/r_reference/generate_golden.R`), including QMP, American Gut Round 1, GlobalPatterns, synthetic `counts=False`/parameter-variation cases, and an R-failure stress case.
Tests: `tests/test_equivalence.py` (marker `slow`).

## How equivalence is established

1. The R generator stamps out two cases from the public SPRING QMP dataset:
   `qmp_n106_p20` (all 106 samples, 20 zero-rich taxa) and `qmp_n20_p30`
   (20 observed samples, 30 taxa, so `p > n`). Both use `counts=True` and the
   same pseudo-count path used for zero-containing data.
2. For every case the generator **replays** the R RNG so the bootstrap indices and the
   artificial-null draws are saved (1-based / raw) and asserted exact.
3. The Python tests inject those arrays and compare, reporting the **first step that
   diverges**.

## Fixture coverage

The committed golden set covers both data branches and non-default parameters:

- `counts=True` with the pseudo-count/normalisation path (QMP, American Gut
  Round 1, GlobalPatterns).
- `counts=False` (inputs already treated as compositional) via the synthetic
  `synth_frac_*` cases.
- Varied `k_cv` (3, 4, 5), `n_boot` (3–7) and non-default `lam_int` intervals
  (`(1e-3, 1e-1)`, `(1e-5, 1)`) in the `synth_*` cases.

`tests/test_equivalence.py::test_golden_matrix_covers_counts_false_and_parameter_variation`
asserts this coverage so it cannot silently regress. Synthetic inputs are
deterministic logistic-normal draws generated inside `generate_golden.R` and
carry no third-party data-provenance constraints.

## Measured deviations (Linux x86-64, R 4.6.1 vs NumPy 2.5.4 / SciPy 1.18.1)

Maximum absolute deviation over the two QMP cases:

| quantity | max abs deviation | tolerance enforced |
|---|---|---|
| log-transform matrix (`x_log`) | 3.6e-15 | rtol 1e-10, atol 1e-12 |
| `lams` (λ path, log10) | **0 (bit-identical)** | rtol 1e-12, atol 1e-15 |
| `fvals` (CV loss) | 1.21e-10 | rtol 1e-6, atol 1e-8 |
| `lambda` (selected) | **0 (bit-identical)** | rtol 1e-12, atol 1e-15 |
| `var_w` | 9.14e-12 | rtol 1e-6, atol 1e-8 |
| `cor_w` | 8.22e-14 | rtol 1e-6, atol 1e-8 |
| `p_vals` | 1.48e-13 | rtol 1e-6, atol 1e-8 |
| ADMM iteration counts | **exact (all calls)** | exact |
| number of CV evaluations (`info_cv.k`) | **exact** | exact |
| λ path length | **exact** | exact |

In practice the port is **bit-identical** for the deterministic quantities and within
~1e-13 for the ADMM-driven ones. The looser final tolerances (1e-6) are kept deliberately
because they are the realistic bound on other BLAS/LAPACK builds (see below); they are
**not** a licence to accept larger errors.

## Tolerance justification

- `lams`, `lambda`, `info_cv.k`, path length, ADMM iteration counts: pure arithmetic /
  integer control flow that does not depend on BLAS. Enforced tight or exact; a failure
  means the golden-section or ADMM path diverged and **must be investigated**, not
  tolerated.
- `fvals`, `var_w`, `cor_w`, `p_vals`: pass through the ADMM solver and BLAS `dsyev`/
  matrix products. On a different BLAS (OpenBLAS vs MKL vs reference), rounding of order
  1e-12…1e-15 can accumulate; 1e-6 is a safe ceiling that still catches any real bug.

## Guaranteed identical (given injected indices)

- The transformed data matrix and the covariance-by-row-weights `wd`.
- The entire golden-section control flow: trial points, branch decisions, λ values,
  λ path length, number of CV evaluations.
- The ADMM iteration count of every `cclasso_sub` call (CV, bootstrap, null sample).
- Selected λ.

## Identical within numerical tolerance

- CV loss values, `var_w`, `cor_w`, `p_vals` (observed ~1e-13, contract 1e-6).

## Cannot be identical (by construction)

1. **RNG**: R's `sample()`/`rnorm()` ≠ NumPy's Generator. Without injected indices the
   bootstrap and artificial-null values differ; results are *statistically*
   equivalent, not identical. This is why the API exposes `boot_indices` / `null_norm`.
2. **BLAS/LAPACK**: different `dsyev`/GEMM implementations produce ~1e-12…1e-15
   differences that can shift an ADMM iteration count by ±1 near the stopping threshold.
3. **Eigenvectors**: defined up to sign, and up to an arbitrary basis inside repeated
   eigenvalues. The algorithm only uses basis-invariant combinations — proven in
   `docs/PORTING_NOTES.md` §5.1 and confirmed empirically by the bit-identical `lams`/
   `lambda` above — so this introduces **no** difference.

## Note on non-convergence / NaN

As in R, when the ADMM reaches `k_max` (200) without satisfying `x_tol`, the algorithm
still returns its last iterate; for some datasets this yields a non-PSD covariance with a
negative diagonal, hence `NaN` variances/correlations. The port reproduces this behaviour
(it does **not** "fix" it) so that results stay equivalent to R.

The exact NumPy-seeded non-finite case has now been replayed through R with the same
input, bootstrap indices, and null draws. Both implementations produce the negative
bootstrap variance at the same taxon/replicate, and the same eight non-finite positions
in `cor_w` and `p_vals`; Python represents these as NaN and R as NA. Finite outputs
agree to at most `8.19e-14` in the replay. This is shared behavior, not a Python-only
mismatch, but those non-finite estimates are still unusable.

On the two QMP cases, all 36 and 34 recorded ADMM solves respectively hit the 200-step
cap in both R and Python. Iteration counts match exactly, and the largest terminal
relative-residual difference is `3.96e-14` absolute (`6.33e-12` relative). The largest
observed residual itself is approximately `1.97e-2` in the smaller-sample `p > n` case.
This is a convergence limitation inherited from the R algorithm; parity must not be
mistaken for proof that those particular estimates have converged to a high-precision
optimum.

The expanded public-data suite adds American Gut Round 1 and GlobalPatterns
cases, with three R-injected bootstrap/null-draw seeds per case family. It
compares matching finite values and exact non-finite masks; non-finite outputs
are not considered valid estimates. The prevalence-spread GlobalPatterns
`n=26,p=40` seed 3102 is retained separately as an expected R error and now
raises the matching Python error instead of returning an estimate.

## Extra diagnostic field

`cclasso()` returns private diagnostic keys `_admm_iters`, `_admm_relative_errors`, and
`_bootstrap_variances` for the equivalence/stability tests. These are **not** part of
the R output and are stripped by the CLI. All public output keys match the R list.

## Reproduce

```bash
# (re)generate fixtures (needs R)
Rscript tests/r_reference/generate_golden.R tests/golden
# run the equivalence tests (no R needed)
pytest tests/test_equivalence.py -m slow -q
```
